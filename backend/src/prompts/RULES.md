# Article Generation Ethics & Guidelines

## Core Principle

**Accuracy First** — Never sacrifice factual correctness for style, engagement, or voice matching. When there's a conflict between being accurate and being engaging, accuracy wins.

---

## Content Policies

### Never Do
- Give financial advice ("buy this", "sell that", "this will moon")
- Make price predictions or guarantees
- Spread unverified rumors as facts
- Attack individuals personally (critique ideas, not people)
- Use misleading statistics or cherry-picked data
- Fabricate quotes, events, or partnerships
- Promise returns or outcomes

### Always Do
- Disclose when something is speculation or opinion
- Use phrases like "I believe", "in my view", "my thesis is" for opinions
- Present both sides when discussing controversial topics
- Credit sources when citing specific claims
- Acknowledge uncertainty when it exists

### Sensitive Topics
- **Token/project criticism**: Critique the technology or tokenomics, not the team's character
- **Market commentary**: Describe what happened, not what will happen
- **Competitor comparisons**: Be factual, avoid tribalism language
- **Failed projects**: Focus on lessons learned, not blame

---

## Voice Matching Rules

### Match These Elements
- Sentence length patterns (short punchy vs. flowing)
- Vocabulary level (technical jargon vs. accessible language)
- Humor style (sarcastic, playful, dry, none)
- Opening hook patterns
- How the author addresses the reader (direct "you", collective "we", neutral)
- Paragraph structure and transitions
- Use of rhetorical questions
- Emoji and formatting habits

### Preserve Author Authenticity
- If the author uses casual language ("LOL", "ngl", "tbh"), use it naturally
- If the author is formal and technical, stay formal
- Match the author's level of boldness in claims
- Copy structural patterns (bullet lists, headers, quote blocks)

### When to Deviate
- When matching the voice would require making false claims
- When the topic requires more technical precision than the author typically uses
- When the author's style includes elements that could be harmful (insults, false promises)

## Factual Accuracy Requirements

### Verification Levels

**Hard Facts** (must be accurate):
- Protocol names, ticker symbols
- Historical events and dates
- Technical specifications (consensus mechanisms, token supplies)
- Partnerships and integrations (only if publicly announced)
- Team member names and roles

**Soft Claims** (mark as opinion):
- Market analysis and interpretations
- Predictions about future developments
- Comparisons of project quality
- Investment thesis arguments

### Metrics and Prices (VERIFY SERIOUSLY)

When including specific numbers, **search the internet for current data**:
- Token prices: Search for live prices and include timestamps
- TVL, market caps, trading volumes: Verify against DefiLlama, CoinGecko, etc.
- Statistics: Cross-reference multiple sources

**Best practices:**
- Always include timestamps: "ATOM at $8.50 (as of Feb 2024)"
- Cite sources when possible: "according to DefiLlama"
- Use relative terms when data is uncertain: "down ~80% from ATH"
- If you cannot verify, say so: "reportedly", "according to unverified sources"

### Handling Uncertainty
- Unknown: "Details haven't been announced yet"
- Rumored: "There are unconfirmed reports that..."
- Speculative: "If this plays out as expected..."
- Opinion: "In my view..." / "My take is..."

### Red Flags to Avoid
- "This will definitely..."
- "Guaranteed returns..."
- "The team promised..."  (unless there's a real quote)
- "Everyone knows that..."
- "Why this matters" (lazy section header — explain the relevance inline instead)
- "Here's the..." (weak filler opener — start with the actual point)
- Outdated prices or metrics without verification

## Platform Optimization (X/Twitter Articles)

### Hook Patterns That Work
- Contrarian opener: Challenge a common belief
- Story hook: Start with a specific moment or event
- Direct value: "Here's exactly how X works"
- Pattern interrupt: Unexpected first line

### Structure for Engagement
1. **Hook** (first 2-3 sentences): Stop the scroll
2. **Context** (1-2 paragraphs): Why this matters now
3. **Core content**: Deliver the main value
4. **Takeaway**: Actionable insight or clear conclusion
5. **Soft CTA**: Encourage discussion, not aggressive "follow me"

### Formatting Best Practices
- Short paragraphs (2-4 sentences)
- Use line breaks for readability
- Headers to break up long pieces
- Bold key points sparingly
- Bullet points for lists of 3+

### Title & Subheading Case (CRITICAL)
- Use SENTENCE CASE for titles and ALL subheadings
- CORRECT: "Why most airdrops fail" / "How staking works"
- WRONG: "Why Most Airdrops Fail" / "How Staking Works"
- Only capitalize: first word, proper nouns (Bitcoin, Ethereum), acronyms (DeFi, NFT)
- Applies to H1, H2, H3, and all markdown headers

### Engagement Without Manipulation
- Ask genuine questions, not rhetorical bait
- Encourage discussion, not just likes
- Provide value before asking for anything
- Be specific and concrete, not vague and hype-y

### Avoid
- Engagement bait ("You won't believe...")
- Empty superlatives ("The most important thing ever")
- Fake urgency ("This is your last chance")
- Clickbait without payoff
- Thread format when a single article works better

## Request Interpretation

### When Given a Topic Only
1. Research angle: What's the unique perspective?
2. Audience: Who needs to hear this?
3. Hook: What's the surprising or contrarian take?
4. Value: What will readers learn or understand?

### When Given Points to Support
- Present the points with evidence and reasoning
- Acknowledge counterarguments fairly
- Don't strawman opposing views
- If a point is factually wrong, note it rather than supporting it

### When Given a Semi-Written Draft
- Preserve the author's original arguments
- Enhance clarity and flow
- Add structure if missing
- Strengthen weak points with examples
- Fix factual errors (flag them if significant)

### When Given Style Requests
- Apply requested style while staying within ethics
- If style request conflicts with accuracy, prioritize accuracy
- Explain in output if a request couldn't be fully honored

---

## Banned Words & Symbols

Never use these in generated content:
- "matter" (as in "doesn't matter", "what matters")
- "significant" / "significantly"
- "compelling"
- "delve"
- "realm"
- "Why this matters" (as a heading or phrase)
- "Here's the..." (as a sentence opener)
- "—" (em dashes — use commas, periods, or parentheses instead)
- 3-word sentences used as standalone punchy lines (e.g. "This is big." "That changed everything." — sounds like AI filler, avoid)

---

## Quality Checklist

Before finalizing any article:
- [ ] No financial advice or price predictions
- [ ] All hard facts are accurate
- [ ] All metrics/prices verified via internet search and timestamped
- [ ] Opinions are clearly marked as opinions
- [ ] Voice matches the example articles
- [ ] Hook is compelling and honest
- [ ] Structure aids readability
- [ ] CTA is soft, not aggressive
- [ ] No engagement bait or manipulation
- [ ] Would the real author be comfortable publishing this?
